1 · First move

Say this in an interview: “Brute force compares all pairs. I can instead scan once and keep a set of IDs seen so far. If the current ID is already in the set, I return true; otherwise I insert it. That's O(n) expected time.”

2. Hash maps and sets

The single highest-payoff trick: remember something useful instead of searching for it again.

Recognition clue

Seen before, count/frequency, match by ID, pair adding to X, group by key.

seen = set()
for x in nums:
    need = target - x
    if need in seen:
        return True
    seen.add(x)

Teaching drill · Pair to target

Prices are [4, 7, 1, 8]. Find whether two different prices total 9.

1 · What should you remember while scanning?
2 · Which ordering avoids matching an item with itself?
3 · Edge cases worth saying aloud
Turn “x + ? = target” into “? = target − x.”
Model reasoning: “For every x, the only useful partner is target−x. A set lets me ask whether that value appeared earlier in O(1) expected time, so the whole scan is O(n).”

3. Graphs: things connected to things

A graph is just objects (nodes) plus relationships (edges). Product relationships, dependencies, and identity links naturally become graphs.

graph = {
  'A': ['B','C'],
  'B': ['A','D'],
  'C': ['A'],
  'D': ['B']
}

Breadth-first search

Explore distance 0, then 1, then 2. Use it for fewest equal-cost steps.

q = deque([start]); seen = {start}
while q:
    u = q.popleft()
    for v in graph[u]:
        if v not in seen:
            seen.add(v)      # when queued
            q.append(v)

Depth-first search

Follow one route deeply, then backtrack. Great for “visit everything reachable,” components, and recursive structure.

Teaching drill · Related-product hops

Each edge means “related product.” Find the minimum number of relationships from product A to product Z. Every edge counts as one hop.

1 · Algorithm family
2 · When should a node become “seen”?
Ask whether all moves cost the same. If yes, BFS layers correspond exactly to distance.
Model reasoning: “This is an unweighted shortest-path problem. I'll BFS from A, storing each node's distance or processing level by level. The first time I discover Z is the minimum number of hops.”

4. Union-Find: keep track of merged groups

Also called Disjoint Set Union. Ignore the name: it answers “which group is x in?” and “merge these two groups.”

find(x)      → representative of x's group
union(a,b)   → merge a's and b's groups

A=B, B=C  ⇒  {A,B,C}

Teaching drill · Product identity stream

Signals arrive: A matches B, D matches E, B matches C, C matches D. You need to maintain product identity groups as signals arrive.

1 · Best fit
2 · Final grouping
Transitivity is the key: matching need not be direct.
Model reasoning: “Each match is an edge saying two records belong to one component. Since updates are mostly unions and connectivity/group queries, Union-Find is a natural fit. Path compression keeps repeated find operations very cheap.”

RETRIEVAL

5. Heaps: don't sort a billion things to keep 100

A heap keeps the next smallest priority cheap. Maintaining a size-K heap is the standard “best K from a huge stream” move.

heap = []
for score in scores:
    heappush(heap, score)
    if len(heap) > k:
        heappop(heap)
# the k largest scores remain

Teaching drill · Retrieval shortlist

A candidate generator streams 100 million product similarity scores. Keep the best 50.

1 · Choose the strategy
2 · Target complexity
The heap should contain winners, so which winner should be easiest to evict?
Model reasoning: “K is tiny relative to n. I'll keep a min-heap of the current K largest scores. The root is the weakest current winner, so when the heap exceeds K I pop it. Time is O(n log K), space O(K).”
Similar: Top K Frequent

6. Dependencies: what can happen next?

“Topological sort” is simply ordering tasks so every prerequisite comes first.

Count each node's unmet prerequisites. Start with everything at zero. Process one; decrement the prerequisite counts of things it enables. If items remain but none reach zero, there is a cycle.

Teaching drill · Catalog pipeline dependencies

Normalize must precede Match; Match and Enrich must both precede Publish. Determine whether all stages can run and produce one valid order.

1 · What should enter the queue initially?
2 · Cycle signal
Think “what is legal right now?” rather than “what comes first globally?”
Model reasoning: “This is a directed dependency graph. I'll use indegrees: queue every node with indegree zero, repeatedly remove one and decrement its dependents. If I process every stage, the order is valid; otherwise a cycle exists.”

7. Sliding window: don't restart every substring

Expand the right side; when invalid, move the left side until valid again.

Teaching drill · Longest unique run

Find the longest contiguous run of event types with no repeated type.

1 · What makes the current window invalid?
2 · Repair step
The window always represents a candidate answer satisfying one invariant.
Model reasoning: “I'll maintain a set for the current window. As right advances, if s[right] is already present, I advance left and remove characters until the duplicate leaves. Each character enters and leaves at most once, so O(n).”

8. Prefix sums: current total minus an old total

If cumulative total now is P, then a previous cumulative total P−K identifies a contiguous region summing to K.

freq = {0: 1}
prefix = answer = 0
for x in nums:
    prefix += x
    answer += freq.get(prefix-k, 0)
    freq[prefix] = freq.get(prefix,0) + 1

Teaching drill · Count target-sum windows

Values may be positive or negative. Count contiguous subarrays summing to K.

1 · Why not a standard sliding window?
2 · Why start freq with {0:1}?
Write the equation: currentPrefix − oldPrefix = K.
Model reasoning: “For each current prefix P, any earlier prefix P−K creates a target-sum subarray ending here. I'll count prior prefix values in a dictionary, seeded with zero once.”

The interview version is broader than looking up a value in a sorted array.

capacity:  1  2  3  4  5  6

                     ↑ smallest yes

Teaching drill · Minimum throughput

Choose the smallest processing rate that finishes all batches by a deadline.

1 · What property permits binary search?
2 · If mid is feasible and you want the minimum feasible value?
Separate the problem into “guess an answer” and “can I check this guess cheaply?”
Model reasoning: “I'll binary-search the rate. For a candidate rate, a linear feasibility function computes whether all work finishes by the deadline. Because faster rates can never make a feasible schedule infeasible, the predicate has a false→true boundary.”

10. Trees: stop thinking about the whole tree

Ask: “If each child already solved its subtree, what information do I need back?”

def height(node):
    if node is None: return 0
    return 1 + max(height(node.left), height(node.right))

Teaching drill · Validate ordered hierarchy

A binary-search tree requires every value in a node's entire left subtree to be smaller and every value in its entire right subtree to be larger.

1 · Is checking only immediate children enough?
2 · What is the useful recursive contract?
For the left child, the current node becomes a new upper bound. For the right child, it becomes a new lower bound.
Model reasoning: “I'll recursively validate each node inside an allowed interval. The left subtree inherits the current lower bound and uses node.val as its upper bound; the right does the opposite.”
Similar: Validate BST

11. Dijkstra: shortest path with nonnegative costs

BFS assumes every move costs the same. Dijkstra always expands the cheapest known unfinished route.

Teaching drill · Relationship costs

Edges have nonnegative penalties representing relationship uncertainty. Find the minimum-penalty path from A to every product.

1 · BFS or Dijkstra?
2 · Python heap has no convenient decrease-key. What do you do?
The heap stores candidate routes ordered by total distance so far.
Model reasoning: “I'll keep best-known distances and a min-heap of candidate (distance,node) pairs. Pop the cheapest; if it's stale, skip it. Relax each outgoing edge and push any improvement.”

Recognition sheet

Seen before / counts / lookup by key → set or dictionary
Fewest equal-cost steps → breadth-first search
Visit everything reachable / count groups → breadth- or depth-first search
Repeatedly merge identities/groups → Union-Find
Prerequisites / dependency order → topological ordering
Best K / kth best / priority → heap
Weighted shortest path, nonnegative costs → Dijkstra
Longest/shortest contiguous region → sliding window if validity changes monotonically
Subarray sum with negatives → prefix sums + dictionary
Minimum X that makes a test pass → binary search on the answer
Tree recursion → define what each child/call returns
Same smaller optimization problem repeats → dynamic programming
