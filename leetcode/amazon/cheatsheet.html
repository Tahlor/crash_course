Recognize the smell. State the invariant. Avoid the bug.

This is the dense page to reread right before the interview. Every abbreviation is expanded once; the goal is retrieval, not teaching from scratch.

0. What to do when the problem appears

  1. Restate the input/output. Ask about constraints and ambiguous edge cases.
  2. Say the simple solution first. It proves you understand the problem even if it is slow.
  3. Name the repeated expensive operation. “I keep searching earlier values,” “I recompute every substring,” “I sort far more candidates than I need.”
  4. Choose the structure that makes that operation cheap.
  5. State one invariant. This is more useful than reciting an algorithm name.
  6. Say time and space complexity. Then code.
  7. Dry-run one normal case and one dangerous edge case.

1. Pattern trigger map

Hash map / set

Smell: seen before, duplicate, count, frequency, pair/match by value or ID.

Thought: What repeated lookup can I make approximately constant time?

Invariant: the dictionary/set summarizes everything useful from the processed prefix.

Bug: when self-match is illegal, often check before insert.

Breadth-first search (BFS)

Smell: fewest steps/hops in an unweighted graph; explore level by level.

State: queue + seen set.

Invariant: queued nodes are already marked seen; queue order follows nondecreasing hop distance.

Bug: mark seen when enqueueing, not later when dequeueing.

Depth-first search (DFS)

Smell: visit everything reachable, connected components, recursive tree/graph exploration.

State: recursion stack or explicit stack + seen.

Question: do I need shortest distance? If yes, plain DFS is usually not it.

Union-Find / Disjoint Set Union

Smell: repeated merges, “same group?”, transitive identity: A=B and B=C.

Operations: find(x) representative; union(a,b) merge.

Invariant: items with the same representative are in the same component.

Know: path compression; union by size/rank is the usual partner optimization.

Topological sort

Smell: prerequisites, dependencies, legal order, detect dependency cycle.

State: adjacency list + indegree = unmet prerequisite count + queue.

Invariant: queue contains only nodes legal to process now (indegree zero).

Cycle: processed fewer than all nodes.

Heap / Top K

Smell: best K, nearest K, highest K from huge stream; K ≪ n.

Thought: do not fully sort losers I will discard.

Invariant: size-K heap contains the best K candidates seen so far.

For K largest: min-heap root = weakest winner.

Sliding window

Smell: contiguous range, longest/shortest substring/subarray, validity can be repaired by moving left forward.

Invariant: current [left,right] window satisfies the rule.

Mechanic: expand right; while invalid, shrink left.

Warning: arbitrary negative numbers often destroy simple sum-window monotonicity.

Prefix sum + dictionary

Smell: exact contiguous subarray sum/count, especially with positive and negative numbers.

Equation: currentPrefix − oldPrefix = K ⇒ oldPrefix = currentPrefix − K.

Invariant: map contains prefix sums strictly before the current position.

Bugs: seed {0:1}; query before incrementing current prefix count.

Binary search on the answer

Smell: smallest/largest value that makes a feasibility check pass.

Shape: false false false | true true true.

Thought: binary-search possible answers, not necessarily an input array.

Boundary: if mid works and may be the first working answer, keep it: often hi = mid.

Dijkstra shortest path

Smell: minimum total cost/distance with different nonnegative edge weights.

State: best distance per node + min-heap of candidate distances.

Invariant: heap exposes the smallest tentative total distance.

Python trick: push improved entries again; skip stale pops with if d != dist[u]: continue.

Sort + sweep / two pointers

Smell: intervals, pair relations, “would ordering make interactions local?”

Thought: pay O(n log n) once so the rest becomes a linear scan.

Two pointers: often one or both indices only move forward/inward.

Trees + recursion

Smell: hierarchical structure, subtree property, aggregate child information.

Question: if each child already solved its subtree, what exactly must it return to its parent?

Always define: recursive contract + base case before writing the body.

Dynamic programming (DP)

Smell: choices create the same smaller subproblem repeatedly.

Start: define the state completely, recurrence, and base case.

Fast interview path: top-down recursion + memoization (@cache) is often easiest to derive.

2. The confusions that matter

BFS vs Dijkstra
Every move costs the same → BFS. Different nonnegative costs → Dijkstra.
DFS/BFS vs Union-Find
One/few static traversals → graph search is simple. Repeated merges / connectivity queries over time → Union-Find shines.
Sliding window vs prefix sum map
Window validity changes predictably as boundaries move → window. Exact sums with arbitrary negatives → prefix sum + map is often the clue.
Full sort vs heap
Need global ordering → sort. Need only best K with K small → heap.
Ordinary binary search vs binary search on answer
You are allowed to search any ordered/monotonic candidate space, not only a sorted input array.

4. Complexity: enough to speak clearly

O(1)roughly constant: dictionary/set lookup on average
O(log n)repeatedly cut possibilities in half; one heap operation
O(n)one pass over all input
O(n log n)typical comparison sort; often perfectly good
O(n²)all pairs / nested full scans; suspicious when n is large

Interview habit: say what operation causes the complexity. “I visit every node and edge once,” or “each of n candidates costs log K heap maintenance,” is stronger than reciting a symbol.

5. Dangerous edge cases

empty inputsingle itemduplicatesstart = goaldisconnected graphcycleno solutionmultiple valid answersnegative valuesK = 0 / K > n

Do not mechanically list all of these. Name the two or three that could actually break your algorithm or change the interpretation.

6. For this Amazon role, overlearn these five

  1. Graphs: related items, traversal, components, shortest hops.
  2. Union-Find: product/listing identity and transitive grouping.
  3. Heap / Top K: candidate retrieval and keeping a shortlist at scale.
  4. Topological sort: dependencies and cycle detection.
  5. Dijkstra: weighted relationship/path cost when edge costs differ.

Then be solid on hashing, sliding windows/prefix sums, binary search, sorting, and basic tree recursion.
