1. Big-O + the Python toolbox

First learn how interviewers talk about speed, and the five Python containers you will use everywhere.

The whole point of Big-O

Big-O describes how work grows as the input grows. You usually only need these:

O(1)       constant: dictionary lookup
O(log n)   repeatedly cut the search space in half
O(n)       scan everything once
O(n log n) typical good sort
O(n²)      compare every thing with every other thing

If there are one million products, an O(n) pass is about a million units of work; O(n²) is about a trillion. That is why a clever dictionary can matter.

Python containers

list     []        ordered items; append/pop end are fast
set      set()     unique items; fast "have I seen x?"
dict     {}        key → value; fast lookup/counting
deque    deque()   queue; fast add-right/remove-left
heapq              quickly retrieve the smallest item

Trap: Removing the first item from a normal Python list is slow because every later item shifts. Use collections.deque for a queue.

30-second check: You scan 10 million IDs and want to know whether each has appeared before. List or set?
A set. Membership is normally O(1); searching a list is O(n), which accidentally makes the whole scan O(n²).

2. Hash maps and sets

The highest-payoff interview trick: remember useful information instead of searching for it again.

Recognize it

Clues: “seen before,” duplicate, frequency/count, match by ID, pair adding to X, group records by key.

The idea

Suppose numbers are [4,7,1,8] and you need two that add to 9. When you see 8, you need to know whether 1 appeared earlier. Store earlier numbers in a set.

seen = set()
for x in nums:
    need = target - x
    if need in seen:
        return True
    seen.add(x)

Instead of checking every pair, each number asks one fast question. O(n²) becomes O(n).

Counting

counts = {}
for x in items:
    counts[x] = counts.get(x, 0) + 1

Trap: Decide whether to check before inserting. In Two Sum, inserting first can let an item match itself.

Check: You need the most common product category. What do you store in the dictionary?
category → count. Scan once to count; then find the maximum count.

3. Sorting + two pointers

Sorting can turn a messy global problem into a simple left-to-right scan.

Recognize it

Clues: intervals overlap, pairs in a sorted array, nearest neighbors, “can ordering make this local?”

Two pointers

For a sorted list, one pointer starts left and one right. If the sum is too small, move left upward; if too large, move right downward.

nums.sort()
left, right = 0, len(nums)-1
while left < right:
    s = nums[left] + nums[right]
    if s == target: return True
    if s < target: left += 1
    else: right -= 1

Intervals

Sort intervals by start time. Now only the current merged interval can overlap the next one.

Trap: Sorting costs O(n log n). That is often excellent, but say the cost aloud.

Check: Why does sorting help merge intervals?
After sorting by start, if the next interval does not overlap the current merged one, it cannot overlap any earlier interval either. The relevant comparison becomes local.

4. Graphs: breadth-first and depth-first search

Products and their relationships naturally form graphs. A graph is just things (“nodes”) connected by relationships (“edges”).

Represent a graph

graph = {
  "A": ["B", "C"],
  "B": ["A", "D"],
  "C": ["A"],
  "D": ["B"]
}

Breadth-first search (BFS)

Think BFS for fewest steps when every edge costs the same. It explores layer 0, then layer 1, then layer 2.

from collections import deque
q = deque([start])
seen = {start}
while q:
    u = q.popleft()
    for v in graph[u]:
        if v not in seen:
            seen.add(v)      # mark WHEN queued
            q.append(v)

Depth-first search (DFS)

Think DFS for “explore everything reachable,” components, cycles, or tree-like recursion. Follow one path deeply, then back up.

def dfs(u):
    seen.add(u)
    for v in graph[u]:
        if v not in seen:
            dfs(v)

Trap: BFS marks a node seen when adding it to the queue, not later when removing it. Otherwise several parents can enqueue the same node.

Check: Unweighted friendship graph; find minimum number of introductions from A to Z. BFS or DFS?
BFS, because it explores by distance in number of edges. The first time you reach Z is a shortest path.

5. Union-Find: “these belong to the same group”

Also called Disjoint Set Union. The name is worse than the idea.

Recognize it

Clues: repeatedly merge identities/groups; “A matches B and B matches C”; are X and Y connected?

The idea

Every item points toward a representative of its group. find(x) asks “which group?” union(a,b) merges two groups.

parent = list(range(n))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]  # shorten path
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[rb] = ra

Example: union(A,B), then union(B,C). Now find(A), find(B), find(C) all return the same group representative.

Trap: Do not compare parent[a] == parent[b]. Parents may be intermediate. Compare find(a) == find(b).

Check: Seller listings A=B, B=C, D=E arrive as a stream. What are the final groups?
{A,B,C} and {D,E}. Transitive matching is exactly what Union-Find captures.

6. Dependencies: topological ordering

A fancy name for “what can I do next if prerequisites exist?”

Recognize it

Clues: prerequisites, dependencies, valid order, build order, cycle makes completion impossible.

The idea

Count how many prerequisites each item still has. Start with all items having zero. Process one, remove its outgoing dependencies, and anything that reaches zero becomes available.

q = deque(nodes_with_zero_prereqs)
processed = 0
while q:
    u = q.popleft(); processed += 1
    for v in graph[u]:
        indegree[v] -= 1
        if indegree[v] == 0:
            q.append(v)

has_cycle = processed != number_of_nodes

Trap: Edges have direction. Decide explicitly whether A → B means “A enables B” or the reverse.

Check: A needs B, B needs C, C needs A. Why does the queue start empty?
Every node has one unmet prerequisite. There is no legal starting point, revealing the cycle.

7. Heaps: keep the best few without sorting everything

Extremely natural for candidate retrieval: best K out of a huge stream.

Recognize it

Clues: top K, kth largest/smallest, repeatedly need current smallest/largest, priority scheduling.

The idea

A heap is a structure where retrieving the smallest item is cheap. Python's heapq is a min-heap.

import heapq
heap = []
for score in scores:
    heapq.heappush(heap, score)
    if len(heap) > k:
        heapq.heappop(heap)
# heap contains the k largest scores

Why? The heap is allowed to hold only K winners. Whenever K+1 appear, throw away the smallest.

Trap: Python gives the smallest item first. For a max-heap, a common trick is to store negative values.

Check: 1 billion candidate products; need best 100. Why not sort all 1 billion?
Sorting all costs O(n log n). Maintaining a 100-item heap costs O(n log 100), and memory stays tiny.

8. Dijkstra: shortest path when edges have costs

BFS is for equal-cost steps. Dijkstra is the upgrade when relationships have nonnegative weights/costs.

Recognize it

Clues: cheapest/shortest route in a weighted graph; all edge weights are nonnegative.

The idea

Always expand the currently cheapest known unfinished route. A heap tells you which one that is.

dist = {start: 0}
heap = [(0, start)]
while heap:
    d, u = heapq.heappop(heap)
    if d != dist[u]:
        continue  # stale older route
    for v, cost in graph[u]:
        nd = d + cost
        if nd < dist.get(v, float('inf')):
            dist[v] = nd
            heapq.heappush(heap, (nd, v))

Trap: Dijkstra is not correct with negative edge weights.

Check: All roads count as one hop. Dijkstra or BFS?
BFS. Dijkstra works, but BFS is simpler and exploits equal edge costs.

9. Sliding window: maintain a moving contiguous chunk

Avoid recomputing every substring/subarray from scratch.

Recognize it

Clues: longest/shortest contiguous substring or subarray; maintain a condition while moving right.

The idea

Expand the right edge. If the window becomes invalid, move the left edge until it becomes valid again.

left = 0
seen = set()
for right, ch in enumerate(s):
    while ch in seen:
        seen.remove(s[left])
        left += 1
    seen.add(ch)
    best = max(best, right-left+1)

Trap: “Subarray” does not automatically mean sliding window. If values can be positive and negative, validity may not change monotonically when left moves.

Check: “Longest substring with no repeated character.” What makes the window invalid?
The new character already exists in the current window. Move left and remove characters until that duplicate is gone.

10. Prefix sums: turn range sums into subtraction

A cumulative total plus a dictionary solves a surprisingly common family of subarray questions.

Start simple

For [2,3,5,4], cumulative totals are [2,5,10,14]. Sum from index 1 through 3 is total-through-3 minus total-before-1: 14 - 2 = 12.

The interview trick

If current cumulative total is P and you want a prior point that makes the intervening sum K, you need a prior cumulative total of P-K.

freq = {0: 1}
prefix = answer = 0
for x in nums:
    prefix += x
    answer += freq.get(prefix - k, 0)
    freq[prefix] = freq.get(prefix, 0) + 1

Trap: {0:1} matters: it represents the empty prefix and lets a subarray starting at index 0 count.

Check: Why do we store how many times each prefix occurred rather than just whether it occurred?
Because several different starting points can have the same cumulative total, producing several valid subarrays ending here.

11. Binary search: not just searching a sorted array

The powerful version finds the boundary where an answer changes from impossible to possible.

Recognize it

Clues: minimum capacity/speed/threshold that makes something possible; maximum value that still works.

candidate: 1  2  3  4  5  6
feasible:  N  N  N  Y  Y  Y
                  ↑ find boundary
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid):
        hi = mid
    else:
        lo = mid + 1
return lo

Trap: You may binary-search only when the predicate is monotonic: once true, it stays true (or once false, stays false).

Check: “Smallest processing rate that completes all jobs by deadline.” What must feasible(rate) answer?
Whether that rate is enough to finish by the deadline. Faster rates remain feasible, giving the false→true boundary.

12. Trees + recursion: ask what a child returns

A tree is a graph with no cycles. Recursion becomes much easier if you define the contract of one function call.

The mental move

Do not think about the whole tree. Ask: if my children already solved their subtrees, what do I need from them?

def height(node):
    if node is None:
        return 0
    left = height(node.left)
    right = height(node.right)
    return 1 + max(left, right)

Binary search tree

For a binary search tree, every value in the left subtree must be smaller and every value in the right subtree larger. The strongest validation passes allowable lower/upper bounds downward.

Trap: Checking only left child < node < right child is insufficient; a deeper descendant can violate an ancestor's bound.

Check: In a recursion for tree height, what does each call return to its parent?
The height of that node's subtree. The parent combines the two child answers with 1 + max(...).
Practice: Validate BST

13. Dynamic programming: cache repeated smaller problems

Lower priority for this short screen, but you should know what the phrase means.

Recognize it

Clues: optimization/counting over many choices; same smaller problem gets solved repeatedly; “best way up to position i.”

The simplest entry

Write a recursive solution and cache each distinct subproblem so it is solved once.

from functools import cache

@cache
def ways(i):
    if i == 0: return 1
    if i < 0: return 0
    return ways(i-1) + ways(i-2)

This turns an exploding recursion tree into roughly one computation per distinct i.

Trap: You need a precise state. If the future answer depends on both position and remaining budget, the cache key needs both.

Check: What is the central question before writing DP?
“What variables completely describe a smaller subproblem?” Those variables define the state/cache key.

14. Three extras worth recognizing

Useful patterns, but do not steal time from graphs, hashing, heaps, and basic search.

Stack

Last-in-first-out. Python list works: append(), pop(). Think nested parentheses, undo, next greater/smaller.

Backtracking

Systematically try choices: choose → recurse → undo. Think subsets, permutations, combination search.

path.append(choice)
search(...)
path.pop()   # undo

Multi-source BFS

If you need distance to the nearest one of many sources, put all sources into the initial BFS queue. One outward wave solves everything at once.

Check: Each grid cell wants distance to nearest hospital. Run BFS from every cell?
No. Put all hospitals into the queue at distance 0 and run one multi-source BFS.

The recognition sheet

Seen before / count / match by key → set or dictionary
Fewest equal-cost steps → breadth-first search
Explore everything reachable / count groups → depth-first search or breadth-first search
Repeatedly merge identities/groups → Union-Find
Prerequisites / dependency order → topological ordering
Best K / kth best / priority → heap
Shortest weighted path, nonnegative weights → Dijkstra
Contiguous longest/shortest stretch → sliding window (if validity behaves monotonically)
Subarray sums, especially with negative numbers → prefix sums, often + dictionary
Minimum X that makes a test pass → binary search on the answer
Hierarchy/tree recursion → define what each child returns
Repeated overlapping smaller optimization problems → dynamic programming
